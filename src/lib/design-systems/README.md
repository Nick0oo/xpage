# XPage visual grammar and generation baseline

XPage uses a small, brief-ranked visual vocabulary rather than a fixed theme picker. `catalog.ts` chooses an applicable system from the brief; `design-plan.ts` records its design DNA and content inventory; `design-templates/compositions.ts` offers section-level structures with fit and anti-pattern checks; `agent/skills/frontend-design/SKILL.md` integrates those rules into the implementation procedure. The prompt route invokes system selection and the enumerable-content audit as generation steps. The HTML route checks the required section IDs and copy in the final DOM, repairing once and returning an explicit failure if required content is still absent.

## XPage rules

- A design system is a compositional reference, not a hard-coded palette. `designDNA` is the one source of truth for the final brand tokens.
- Each planned section gets one content task and a composition suited to that task. Recipe IDs are selected from brief-fit candidates; repeated cards, splits, and Bento grids need a specific reason.
- Enumerable deliverables are extracted from the offer before model generation, required in the plan, and validated again in the HTML DOM. A model repair is attempted once; unresolved omissions fail with the missing-item report instead of producing a ready landing.
- The generation skill contains the detailed design-system procedure so it stays available during plan and HTML generation without adding a new plugin system.
