# Ficha de investigación · Creador y crítico

Versión: 1.0.0 · 2026-09-28

## Definición y uso
Produce una propuesta visible, una auditoría breve y una revisión explícita. Conviene para revisar jerarquía, comprensión, accesibilidad, credibilidad y fricción antes de generar código.

## Entradas, procedimiento y entrega
Entradas: propuesta y brief. Puntuar problemas observables usando heurísticas generales, comprobar criterios aplicables de WCAG, y registrar cambios concretos. Entregar propuesta, hallazgos y revisión final; no producir cadena de pensamiento.

## Calidad, riesgos y ejemplo XPage
Calidad: cada hallazgo nombra elemento, problema y ajuste. Riesgo: llamar “CRO” a una opinión o atribuir causalidad sin experimento. Ejemplo: detectar que CTA y título compiten por jerarquía y documentar el cambio de orden.

## Fuentes
- Nielsen, [10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/) (heurísticas como reglas generales, no resultados medidos).
- W3C, [WCAG 2.2](https://www.w3.org/TR/WCAG22/) (criterios de accesibilidad comprobables).
