# XPage adaptation overlay (original XPage guidance)

This overlay explains which ideas from the copied resources apply here. It is original XPage material and is not copied from OpenDesign.

- Use the brief and the current plan as authority. Treat identity, audience, offer, constraints, and required content as explicit facts only when supplied; label proposed aesthetic choices as creative proposals.
- Let DesignDNA remain the single source of truth for palette, type, layout, motif, and invariants. A reference package is a source of options, never the active brand unless selected for a clear brief fit.
- Before HTML, give every required content item a home in the section plan. Build a varied sequence around each section's job; choose among a direct thesis, product demonstration, comparison, proof, process, quote, editorial/log list, table, or CTA as the content warrants. Do not route each page through the same hero plus three cards.
- Apply the copied web-prototype library as composition inspiration: select section rhythm before filling copy; alternate structural forms; allow one memorable visual gesture; use concrete action labels; remove filler and unsupported metrics.
- Treat Totality Festival as one example of a vivid system (obsidian, amber corona, cyan atmosphere, cinematic light). Borrow its method of tying palette and effects to a visual premise, not its palette or identity by default.
- Generate inside XPage's standalone HTML/CSS/vanilla-JS contract and sandbox. Adapt any upstream instruction that assumes remote dependencies, plugin tools, app-specific selectors, image fetching or embedding, or a different delivery format. Preserve XPage's required-content, accessibility, mobile, and HTML validation requirements.
- These documents are authored source references copied into the repository. Their presence does not install OpenDesign, add its plugin runtime, or make its tools available.
